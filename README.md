# TDO — laboratorium 02

Mission Control: .NET 10, Angular 21, MySQL. Zadania 1–23 z [instrukcji CI](https://pjmpr.github.io/TDO-lecures/labs/ci/), sprawdzonej w rewizji `442bb25` materiałów kursu.

## Uruchomienie testów

Wymagane: SDK zgodne z `global.json` (10.0.4xx), Node z `.nvmrc` (26.1.0), npm i działający Docker z kontenerami Linux. Testcontainers sam uruchamia MySQL; testy nie potrzebują własnej bazy ani sekretów.

```bash
dotnet restore MissionControl.slnx --locked-mode
dotnet build MissionControl.slnx --configuration Release
dotnet test MissionControl.slnx --configuration Release
cd frontend
npm ci
npm run build
npm test
```

Komplet obejmuje 19 testów API i 11 testów UI. Raporty: `TestResults/backend.trx` oraz `frontend/test-results/{junit.xml,results.json}`. Zależności opisują trzy śledzone lockfiles. Po zmianie pakietów aktualizujemy je lokalnie przez `dotnet restore --use-lock-file` lub `npm install`.

## Workflow

- `ci.yml`: PR do main, push/main i uruchomienie ręczne. Detekcja zmian wybiera backend i frontend; `ci-required` sprawdza wynik wymaganych komponentów.
- `backend.yml` i `.github/actions/backend-check`: reusable workflow oraz wspólne locked restore, build i testy API.
- `inspect-ci.yml`: odczyt metadanych z dokładnego, udanego runa CI typu push/main w tym repozytorium.
- `thesis.yml`: PDF z własnego tekstu, prerelease dla uprawnionego PR-a i pełne wydanie po push/main. [Szczegóły i pochodzenie klasy](thesis/README.md).
- `matrix.yml`: wyłącznie ręczne porównanie konfiguracji. `include-debug=false` daje jeden wariant dynamiczny, `true` daje dwa; obok działają trzy warianty statyczne.

Uruchomienie macierzy: Actions → Matrix lab → Run workflow, albo:

```bash
gh workflow run matrix.yml --ref main -f include-debug=false
gh workflow run matrix.yml --ref main -f include-debug=true
```

Main wymaga PR-a, aktualnej gałęzi i jedynego required checka `ci-required` z GitHub Actions. Bez bypass, force push i usuwania main. Manualne macierze nie są required checks. Praca indywidualna: zero wymaganych akceptacji review. Reguły Classroom pozostają aktywne.

## Cache

Cache obejmuje pobrane paczki npm i NuGet. Instalacja i testy działają również po miss; raporty i katalogi build nie są cache'owane. Czasy dotyczą kroków instalacji, bez transferu cache.

| Próba | Trafienie npm / NuGet | npm ci / restore |
| --- | --- | --- |
| cold | miss / miss | 9 s / 6 s |
| warm, ten sam SHA i ref | exact / exact | 7 s / 4 s |
| nowe lockfiles | miss / miss | 9 s / 6 s |
| nowy namespace | miss / miss | 7 s / 6 s |

[Klucze, pomiary i runy](docs/evidence/cache-stage13.json). Są to pojedyncze pomiary, nie gwarancja przyspieszenia.
